### A3. 第一折：校準診斷

**這一組不是準度，讀法和主表相反。** §60.1 宣告 `y_hat` 是**基數分數、尺度未校正**，所以 MSE / RMSE 量到的主要是**尺度誤差**，不是排序品質。列序仍照 IC 排，於是本表最重要的一件事直接看得到：**MSE 由小到大多半跟著離散比由小到大**（42 列的 Spearman = **+0.75**；不含 [24] 的 32 列是 +0.92，[24] 的預測是收縮的，離散比都小於 1），**它量的不是排序品質**。

錨：`Var(y) = 4.046e-04`（在本欄的單位下是 **0.405**），`std(y) = 2.011%`。`R² = 1 − MSE / Var(y)`，所以 **`MSE (1e-3)` 超過那個值就代表 level R² 是負的**。關鍵是誰沒超過：附表的 `RC 常數對照` （離散比 0.026）**恰好落在 0.405**——一個永遠猜均值的模型正是 `MSE = Var(y)` 的定義。少數低於它的列（`[24] 二部圖 LASSO` 0.374、附表的 `R2（30 檔美股報酬）` 0.373、`[24] 二部圖 RIDGE` 0.381、`[24] 二部圖 ens-med` 0.377、`[24] 二部圖 OLS` 0.384、`[24] 二部圖 ens-avg` 0.378、`[24] 二部圖 RF` 0.378、`[24] 二部圖 AdaBoost` 0.394）靠的是**比常數還往均值縮**，不是靠預測得準——本表 42 列裡有 35 列在 0.405 之上。`src/train/metrics.py:regression_metrics` 的 docstring 早就記了這件事：**MSE 獎勵塌縮**。

另一頭同樣說明問題：附表的 `KTW+` MSE 是 **37.181**（Var(y) 的 92 倍）、離散比 **11.49**，它在主表與附表合計 47 個方法中 IC 第七高。**沒有任何一個方法的 `y_hat` 是校準過的**，所以 MSE 不是一個可以排名次的軸。

後兩欄把負 R² 拆開：`離散比` 說 `y_hat` 的橫截面比 `y` 寬幾倍（1.0 是校準），`校正後 R²` 說**扣掉每日橫截面均值、再把尺度仿射校正之後**還剩多少 level 可解釋變異。它與 `mean IC²` 同量級但不相等（主結果 **0.0135** vs `mean_t(IC_t)² = 0.1090² = 0.0119`），差在攤平的 corr 用橫截面離散度給每天加權。**這一欄才是與 Gu/Kelly/Xiu 那類 level R² 可比的數字。**

## 附錄 D：準度指標，先在 val 定尺度（proposal §68）

**為什麼要這一節。** `y_hat` 是「基數分數、尺度未校正」（proposal §60.1），上面校準診斷的 MSE 量到的是尺度，不能拿來比準度。這一節讓每個模型先站上同一個報酬尺度，再比準度：

1. 每天先扣掉 50 檔的橫截面平均。任務只比相對強弱，沒有模型在預測大盤當天的漲跌。
2. 每個模型在 **val** 上以最小平方擬合一個倍數 `b`（`y ≈ b·y_hat`），固定後套到 test。test 不參與定尺度。
3. test 上算 `RMSE` 與 `R²_oos`，基準是「不選股」：每檔都猜當天平均，`R²_oos = 0`。`命中率` 只用名次，不需要定尺度。

乘一個倍數不改相關係數，所以本節不影響任何 IC / RankIC。**本節是看過示範結果之後才加的，屬描述性，p 值未校正多重比較。**只列主結果、它的集成與附表的線性 baseline。線性 baseline 的 `runs/` 只存 test 預測，val 預測由 `tw_lag_channel.py` / `relational_linear.py` 重算，重算的 test 預測與存檔一致才採用（相對差 ≤ 1e-05）。

## 每一欄怎麼算

記號：某一天的橫截面有 `n` 檔台股，`y_hat` 是預測、`y` 是**實際次日 log return**（`log(Close_t / Close_{t-1})`，`src/dataset/pipeline.py:659`，由 `graph_builder.py` 的 `_extract_target_returns` 取出）。`T` 是**有效交易日數**——50 檔 `y` 或 `y_hat` 完全相同（`nunique() == 1`，相關係數無定義）的日子一律跳過，第一折 246 天扣掉 1 天（該日 50 檔報酬完全相同）得 **T=245**。2026-10-21 以前用 `std() == 0` 判斷：同值的 std 因捨入不一定恰為 0，結果隨 pandas 是否裝了 bottleneck 而不同（proposal §77）。

### 主表與附錄 A 的欄

| 欄 | 算式 | 出處 |
|---|---|---|
| `n` | 種子數。線性／樹模型是確定性擬合（固定設計矩陣上的 `Ridge.fit` 或封閉解），**沒有 seed 可補**，一律 n=1 | `find_seeds` |
| `IC`（主指標） | 逐日 `corr(y_hat_t, y_t)`（Pearson）對 T 天取平均，再跨 seed 取平均。**逐 seed 的值讀自 `meta.json`**（`--predictions reeval` 時改讀 `meta_reeval.json`） | `neural_stats` |
| `ICIR`（附錄 A） | `mean_t(IC_t) / sd_t(IC_t)`，`ddof=1`。**逐 seed 算完再跨 seed 平均**——拿跨 seed 平均後的日序列去算會得到「集成」的 ICIR，系統性偏高 | `icir()` |
| `RankIC`（第二指標） | 同 `IC` 但用 Spearman（平手取**平均名次**，`scipy.spearmanr`）。**一律由預測檔重算，不讀 `meta.json`** | `daily_series` |
| `Rank ICIR`（附錄 A） | `mean_t(RankIC_t) / sd_t(RankIC_t)`，`ddof=1`，逐 seed 算完再平均。**它沒有組合讀法**——`ICIR` 對應 Sharpe 是因為§57.8 的恆等式建立在 Pearson IC 上，`RankIC` 沒有對應的恆等式（§57.3）。它只回答「名次相關本身穩不穩」 | `icir(daily RankIC)` |
| `± sd` | 跨 seed 的樣本標準差，`ddof=1`。n=1 時不印——**那不代表沒有不確定性**，只代表它來自資料而非種子 | `pm()` |
| `逐日 p (IC)` / `逐日 p (RankIC)` | 取「統計基準與該列」的**逐日 IC（或 RankIC）差值序列** `d_t`，做 Newey-West HAC 修正的雙尾 t 檢定；`lag = floor(4 x (T/100)^(2/9))`，T=245 時 **lag=4**，`df = T−1` | `paired_daily` |
| `跨種子 Welch p (IC)`（附錄 A） | 在**共同種子集合**上，對兩組逐 seed 的 IC 做 Welch t 檢定（不假設等變異） | `across_seed` |
| `MW p (IC)`（附錄 A） | 同 Welch，改用 Mann-Whitney U，雙尾。**n=3 時下限是 `2/C(6,3) = 0.1000`**，達不到 0.05 | `across_seed` |

### 校準診斷的欄

**這四欄不是準度指標，是宣告的一致性檢查。** 它們回答「`y_hat` 離 `y` 的尺度有多遠」，不回答「排序對不對」——後者是 IC / RankIC 的事。

| 欄 | 算式 | 出處 |
|---|---|---|
| `MSE (1e-3)` | 攤平所有 (日, 檔) 算 `mean((y_hat − y)²)`，再 x1000。與 `src/train/metrics.py:regression_metrics` 同定義。**它是損失裡 `mse: 1.0` 那一項在測試集上的值** | `calib_stats` |
| `RMSE (%)` | `sqrt(MSE)` 再 x100，與 `std(y)` 同單位可直接比 | `calib_stats` |
| `離散比` | `mean_t[ std(y_hat_t) / std(y_t) ]`，**逐日算完再平均**。與 §60.7 / §52 引用的 2.59（主結果）、1.69（前版 beta）同定義。**不等於** `regression_metrics` 的 `dispersion`（那個攤平算，同一個 arm 給 2.13）——差在攤平版把大盤的跨日變動也算進 `std` | `calib_stats` |
| `校正後 R²` | **先逐日把橫截面均值從 `y_hat` 與 `y` 各自扣掉**，再攤平配 OLS（`y ~ a·y_hat + b`）後的 level R²；代數上等於扣完均值的 `corr²`，故直接用 `corr²` 算。**逐日扣均值是必要的**——不扣會混進「有沒有猜中當天大盤方向」，實測 `R2 ridge` 的日均值相關 +0.5144 會把它的攤平 R² 抬到 0.0940，超過 IC 更高的主結果（0.0173）三倍多；扣完之後是 0.0171 vs 0.0140，回到與 IC 一致的次序。與 `mean_t(IC_t)²` 不相等（0.0135 vs 0.0119）：攤平的 corr 用橫截面離散度給每天加權，`mean IC` 每天等權 | `calib_stats` |

### 組合讀法的欄

**建構**：每天把當日 `y_hat` 由高到低排序，**前 10 檔做多、後 10 檔做空、等權**。權重是 `±1/(2K)`，所以 `sum|w| = 1`（總曝險 1、淨曝險 0），因此當日報酬是

```
r_t = ( mean(y[多腿 10 檔]) − mean(y[空腿 10 檔]) ) / 2
```

那個 `/2` 不可省——不除等於偷偷假設 2 倍槓桿。六個指標**一律逐 seed 算完再平均**，與 `ICIR` 同慣例。

| 欄 | 算式 | 為什麼是這個形式 |
|---|---|---|
| `日均報酬` | `mean(r)` | — |
| `日 sd` | `sd(r, ddof=1)` | — |
| `年化(幾何)` | `exp(mean(r) x 252) − 1` | **`y` 是 log return，所以複利用 `exp` 不是 `(1+r)` 連乘。** 用錯公式在本專案的量級上差約 1.1 個百分點（82.0% vs 83.1%） |
| `Sharpe` | `mean(r) / sd(r) x sqrt(252)`，`rf = 0` | 金額中性多空是**自融資**的，多空相抵不佔用本金，所以無風險利率為 0。淨多頭策略就必須扣 |
| `MDD(複利)` | 權益曲線 `exp(cumsum(r))`，`max_t (peak_t − v_t)/peak_t` | 獲利滾入的讀法 |
| `MDD(加總)` | 權益曲線 `1 + cumsum(r)`，同上取最大回撤 | **獲利不滾入的固定名目本金**。金額中性多空每天重設回同樣曝險，這個讀法才對應實際操作 |

**已移除的兩欄可以自己還原**，它們是純換算、沒有新資訊：

```
年化(簡單) = 日均報酬 x 252          年化波動 = 日 sd x sqrt(252)
Sharpe     = 年化(簡單) / 年化波動    （所以 Sharpe 才是新資訊）
```

**已知近似**：對 log return 取橫截面平均**不等於**等權組合的報酬（後者是簡單報酬的算術平均）。實測差 **+0.14 bp/日 = +0.36 pp/年**，不影響 `Sharpe`，也不影響 §60.4 的打平成本（兩種算法都是 33 bp）。

### §43 專屬的欄

| 欄 | 算式 |
|---|---|
| `離散比 std(y_hat)/std(y)` | 逐日的橫截面標準差之比，對 T 天取平均。**在 ŷ 宣告為「基數分數、尺度未校正」下這是規範選擇不是缺陷**（IC 與 RankIC 都看不到它，proposal §57.11 / §60.7） |
| `其 IC` / `其 RankIC` / `其 ICIR` / `其 Rank ICIR`（B 表） | 該 baseline 自己的值，算法同訊號層（逐 seed 算完再平均） |
| `ICIR` / `Rank ICIR`（A 表） | **兩列的算法刻意不同，這正是 A 表在量的東西**：「先算 IC 再平均」列是**逐 seed** 算完再平均；「先平均預測再算 IC」列是拿**集成後的單一日序列**去算。後者系統性偏高，`增益` 列就是這個差 |
| `增益`（A 表） | 「先平均預測再算 IC」減「先算 IC 再平均」。它是兩列相減，**沒有對應的日報酬序列**，故組合欄留空 |

### 準度小表的欄

下標 `d` 表示扣掉當天 50 檔的橫截面平均；`b` 只用 val 擬合（`b = Σ y_d·y_hat_d / Σ y_hat_d²`）。MAGNET 本版逐 seed 算完再平均（`± sd` 為跨 seed），檢定用跨 seed 平均後的逐日序列；集成列先平均 10 顆的預測再定尺度。日子的取捨同訊號層（50 檔 `y` 完全相同的日子跳過）。

| 欄 | 算式 | 方向 |
|---|---|---|
| `RMSE (%)` | test 上 `sqrt(mean_t mean_j (y_d − b·y_hat_d)²)`，再 x100。`不選股` 列就是當天報酬的橫截面標準差（平方平均） | **↓ 越低越好** |
| `R²_oos` | `1 − Σ_t Σ_j (y_d − b·y_hat_d)² / Σ_t Σ_j y_d²`。分母是「不選股」的誤差，所以 0 = 與不選股一樣，負值 = 比不選股差。與校準診斷的 `校正後 R²` 不同：那一欄的倍數是在 test 上擬合的，只能當上限 | **↑ 越高越好** |
| `命中率` | 每天把 `y_hat` 與 `y` 各自和當天中位數比，落在同一側的比例；剛好等於中位數的不計。50% = 亂猜；常態假設下約為 `50% + arcsin(IC)/π` | **↑ 越高越好** |
| `逐日 p（R²_oos）` | 逐日橫截面 MSE 差的 HAC 雙尾檢定（Diebold–Mariano 檢定），lag 同訊號層 | 無方向 |
| `逐日 p（命中率）` | 逐日命中率差的 HAC 雙尾檢定 | 無方向 |
| `R²_oos 差` / `命中率差`（合併表） | 該列 − MAGNET 本版，兩折的日子一起算；正值代表該列較好 | **↑ 越高越好**（站在該列的立場） |

## 讀表注意

- **欄名的 ↑ / ↓ 是「其他條件相同下哪個方向較好」**，**不是說該欄可以單獨拿來排名**。有四類欄位**刻意沒有箭頭**：<br>(1) **`sd` 各欄**（跨 seed 離散度）——離散度小只代表結果比較不挑種子，一個爛模型的 sd 小並不好，它不是績效；<br>(2) **`逐日 p (IC)` / `逐日 p (RankIC)` / `Welch p` / `MW p`**——這些是**「統計基準對該列」**的檢定與差值，不是該列自己的績效。p 小代表基準顯著贏過該列，站在該列的立場方向是相反的；<br>(3) **`離散比 std(y_hat)/std(y)`**（§43 A 表）——在 ŷ 宣告為「基數分數、尺度未校正」之下，IC 與 RankIC 對仿射變換不變、**兩者都看不到這個比值**，所以它是規範選擇不是缺陷（proposal §57.11、§60.7）；<br>(4) **準度小表的 `逐日 p（R²_oos）` / `逐日 p（命中率）`**——雙尾檢定，**方向看合併表的差值欄**。那裡有線性 baseline 贏過 MAGNET 本版的格子，不能套用 (2) 的「基準贏過該列」。
- **`MDD ↓` 的箭頭尤其不等於可以拿來排名**（見下方 MDD 那條）：它兩折的名次會翻轉。箭頭只說明方向，不背書該欄的可靠度。
- **n 是種子數。** sigma_seed = 0.0062，n=3 的最小可偵測差異為 0.0188、n=10 為 0.0082。n=3 的比較若差異小於 0.019，「不顯著」不構成證據。
- **Mann-Whitney 在 n=3 的雙尾 p 下限是 0.10**（= 2/C(6,3)，`across_seed` 取共同種子集合，故 n=3 的列是 3 對 3），永遠無法達到 0.05。**附錄 A1 九列 n=3 的 MW p 全部恰為 0.1000——那是下界，不是量測值**，不可讀成「接近顯著」；同樣九列的 Welch p 是 0.0000 ~ 0.0016，IC 差距約 0.10 而 sd 約 0.01。n=1（非神經方法）則無法計算，跨種子欄為「—」。
- **第二折表也有 n 與 sd 欄了**（2026-09-14 補）。點估計逐位元未變，只是原本沒把離散度印出來。**但 ICIR 沒有逐日檢定可做**——它是整段期間兩個動差的比值，不存在逐日序列，所以它只有跨種子這一個檢定，而跨種子檢定**不包含日層級的不確定性**（那才是主要來源）。因此 ICIR 的差只能說「兩折同向」，不可升級成「顯著落後」。
- **附錄 A 的組合讀法（六欄）不是回測。** 建構：每天按 `y_hat` 取**Top-10 做多 / Bottom-10 做空、等權、金額中性**（權重 ±1/(2K)，`sum|w|=1`，所以多空腿的報酬差要除以 2），逐日再平衡。**無交易成本、無市場衝擊、無流動性限制、可完全放空**——所以 `Sharpe` 5.86 / `年化` 60% 這種數字**不可以寫成策略績效**（proposal §60.8）。打平成本與成本敏感度見 §60.4 與 `scripts/portfolio_readout.py`：本專案最佳 arm 的打平來回成本是 **33 bp**，而台灣證交稅單項就 30 bp。
- **組合讀法在時序上不可執行**（2026-09-30 補，proposal §61.3(2)）：模型要在 09:00 開盤前給出排序，輸入最晚到美股收盤（台北 04:00／05:00），但 `y` 是前一日 13:30 收盤到當日收盤——隔夜跳空那一段在訊號出現前就開始了。§58.3 的分數加權組合有 **77.9%** 的報酬落在這一段；拿到訊號後能執行的只有盤中腿（09:00 -> 13:30），日均 +0.0415%、逐日 HAC p 0.1395，不顯著。所以組合讀法的六欄**即使成本為零也不是可執行的報酬**，只能當「IC 換算成組合單位」。對照 Qlib：Alpha158 的標籤是 T+1 收盤到 T+2 收盤，標籤本身就是可執行的報酬，它的回測指標才成立；本表的 `y` 沒有這個性質。
- **組合欄的複利用 `exp`，因為 `y` 是 log return**（`src/dataset/pipeline.py:659`）。`年化(幾何)` = `exp(mean(r) x 252) − 1`，`MDD(複利)` 的權益曲線 = `exp(cumsum(r))`；`MDD(加總)` 用 `1 + cumsum(r)`，即獲利不滾入的固定名目本金（金額中性多空每天重設回同樣曝險，這個讀法才對應實際操作）。`年化(簡單)` = `mean(r) x 252`。六欄一律**逐 seed 算完再平均**，與 ICIR 同慣例。**已知近似**：對 log return 取橫截面平均不等於等權組合的報酬（後者是簡單報酬的算術平均），實測差 **+0.14 bp/日 = +0.36 pp/年**，不影響 Sharpe，也不影響打平成本（兩種算法都是 33 bp）。
- **`MDD` 是單路徑極值，一折只有一個觀測值，是六欄裡最不可靠的，而且它兩折的名次是反的**：第一折 MAGNET 4.51% 勝過 KTW+ 5.05%，第二折 1.70% 卻輸給 1.32%。**不要拿 MDD 做任何排名主張。**會翻轉正是它不可靠的直接證據——與 `ICIR` 兩折同向落後恰成對比。
- **逐日 p 用 Newey-West HAC 修正自相關**，以「日」為重複單位、種子視為固定，敏感但不外推到新種子。兩欄應一起看。
- **六個文獻 baseline 各只跑一組預設超參，MAGNET 跑了約 50 組設定。**兩折都只有 3 顆種子（第二折 2026-10-17 補跑，§74）。這是目前最大的公平性缺口，比較結果須據此保留。
- **`log_volume_z` 的資料缺陷不是文獻 baseline 表現差的原因**（2026-09-27 驗證，proposal §55.9(h)）：資料層有 398 列成交量為 0（7 個全市場日期與個股停牌），`log1p(0)` 的離群值讓這個特徵在 26.1% 的股票-日被壓縮（放大倍數中位數 4.63）。六個文獻 baseline 吃的 9 個特徵包含它；MAGNET 主結果 arm 只用 log_return，不受影響。以修正版特徵、同 config 同種子重訓：**IC 平均變動 +0.0006**（18 對，配對 p 0.57，8/18 為正），最大為 HATS +0.0066（3/3 種子，p 0.18）；修正後六個 baseline 仍在 −0.0037 ~ +0.0121。**比較結論不變**，上一條的超參缺口仍是主要保留。重現：`scripts/logvol_fix_check.py`。
- **ICIR = mean(逐日 IC) / sd(逐日 IC)**，逐 seed 算完再跨 seed 平均（不是拿跨 seed 平均後的日序列去算——那是**集成**的 ICIR，系統性偏高；§43 (A) 現在把這個差量出來了：**第一折 +0.0087、第二折 +0.0198**，與 IC 的集成增益 +0.0074 / +0.0130 同量級甚至更大）。**為什麼要看它**：§57.8 的恆等式是 `r_t = IC_t x sigma_t`，所以 IC 只決定組合報酬的**分子**；若 sigma_t 為常數，`Sharpe = ICIR x sqrt(252)`。**與回測 Sharpe 對應的是 ICIR，不是 IC。**實測（§60）本專案最佳 arm 的 IC 高於 KTW+（+0.1090 vs +0.1077）但 ICIR 較低（0.4368 vs 0.4810），Top-10 多空的 Sharpe 也較低（5.86 vs 6.53）——**IC 的排名不保證回測的排名**。
- **`Rank ICIR` 有報，但它沒有組合讀法**（2026-09-15 補；本表原本刻意不報它）。`ICIR` 之所以重要是因為 §57.8 的恆等式 `r_t = IC_t x sigma_t` 建立在 **Pearson** IC 上，所以 `Sharpe = ICIR x sqrt(252)`。**`RankIC` 沒有對應的恆等式**（§57.3：名次加權組合對應的是 `corr(rank(y_hat), r)`，不是 RankIC），因此 **`Rank ICIR` 不可以拿來推論任何組合績效**，它只回答「名次相關本身穩不穩」。補報的理由有二：Qlib / Stockformer 那一系的標準區塊是四個一起報（§60.1），以及 §35.3 發現 `無A₂` 對 RankIC（+0.0077）與 ICIR（−0.0258）方向相反，**需要它才答得出「那個 RankIC 增益本身穩不穩」**。
